Core Java

What is Inheritance?

▼

Inheritance is a mechanism by which one object acquires all the properties and behavior of another object of another class. It is used for Code Reusability and Method Overriding. Inheritance represents the IS-A relationship (parent-child relationship).

class Animal { void sound() { System.out.println("Animal makes a sound"); } } class Cat extends Animal { @Override void sound() { System.out.println("Cat meows"); } } public class TestOverride { public static void main(String[] args) { Animal a = new Cat(); a.sound(); // Calls overridden method in Cat } }

What is Polymorphism?

▼

Polymorphism in Java is a concept by which we can perform a single action in different ways. It is derived from Greek words: poly (many) and morphs (forms). We can achieve polymorphism through method overloading and method overriding.

Method Overloading: Multiple methods with the same name but different signatures (different number, type, or order of parameters).

class Calculator { int sum(int a, int b) { return a + b; } int sum(int a, int b, int c) { return a + b + c; } double sum(double a, double b) { return a + b; } }

Method Overriding: Subclass provides a specific implementation of a method already defined in its superclass.

class Vehicle { void run() { System.out.println("Vehicle is running"); } } class Bike extends Vehicle { @Override void run() { System.out.println("Bike is running safely"); } }

What is Abstraction?

▼

Abstraction is a process of hiding the implementation details and showing only functionality to the user. It displays just the essential things and hides internal information. In Java, abstraction can be achieved through:

  • Abstract Class: Cannot be instantiated, can have both abstract and non-abstract methods
  • Interface: Only abstract methods (prior to Java 8), used for multiple inheritance
// Abstract Class Example abstract class Shape { abstract void draw(); void resize() { System.out.println("Resizing shape"); } } class Circle extends Shape { @Override void draw() { System.out.println("Drawing Circle"); } }

What is Encapsulation?

▼

Encapsulation is a process of wrapping code and data together into a single unit. It involves:

  • Private variables (data hiding)
  • Public getters/setters for controlled access
  • Validation logic in setters
class Student { private String name; private int age; public String getName() { return name; } public void setName(String name) { this.name = name; } public int getAge() { return age; } public void setAge(int age) { if (age > 0) { this.age = age; } } }

What is Reflection in Java?

▼

Reflection allows us to inspect and modify classes, methods, and fields at runtime.

import java.lang.reflect.Method; public class Demo { public void sayHello() { System.out.println("Hello from Reflection!"); } public static void main(String[] args) throws Exception { Class<?> clazz = Demo.class; Method method = clazz.getMethod("sayHello"); Object obj = clazz.getDeclaredConstructor().newInstance(); method.invoke(obj); } }

Java 8+ Features

What are Lambda Expressions?

▼

Lambda expressions provide a clear and concise way to represent a method of a functional interface using an expression. They express an instance of a functional interface.

// No parameter lambda @FunctionalInterface interface Greet { void sayHello(); } Greet greet = () -> System.out.println("Hello, Umesh!"); greet.sayHello(); // Single parameter lambda @FunctionalInterface interface GreetUser { void sayHello(String name); } GreetUser greetUser = (name) -> System.out.println("Hello, " + name + "!"); greetUser.sayHello("Umesh"); // Multiple parameters lambda @FunctionalInterface interface AddNumbers { int add(int a, int b); } AddNumbers add = (a, b) -> a + b; System.out.println("Sum: " + add.add(5, 10));

What are Functional Interfaces?

▼

A functional interface is an interface with exactly one abstract method. It can have any number of default and static methods.

@FunctionalInterface interface MyInterface { void display(); // Only one abstract method default void print() { System.out.println("Default method"); } static void staticMethod() { System.out.println("Static method"); } }

What are Method References?

▼

Method references (::) are shorthand for lambda expressions that call existing methods.

import java.util.Arrays; import java.util.List; List<String> names = Arrays.asList("Umesh", "Rahul", "Amit", "Nisha"); // Using method reference names.forEach(System.out::println); // Equivalent to lambda names.forEach(n -> System.out.println(n));

What is the Stream API?

▼

Stream API is used to process collections of objects with functional style coding using lambda expressions.

import java.util.*; import java.util.stream.*; List<Integer> numbers = Arrays.asList(2, 6, 9, 4, 20); // Filter even numbers List<Integer> evenNumbers = numbers.stream() .filter(i -> i % 2 == 0) .collect(Collectors.toList()); // Map to uppercase List<String> names = Arrays.asList("umesh", "ravi", "neha"); List<String> upperCaseNames = names.stream() .map(String::toUpperCase) .collect(Collectors.toList()); // Sort List<Integer> sorted = numbers.stream() .sorted() .collect(Collectors.toList()); // Reduce (sum) int sum = numbers.stream() .reduce(0, (a, b) -> a + b);

What is the difference between filter and map in Stream API?

▼
Function Purpose
filter() Selects elements based on a condition

List<String> names = Arrays.asList("John", "Jane", "Jack"); // filter - selects elements names.stream() .filter(name -> name.startsWith("J")) .forEach(System.out::println); // map - transforms elements names.stream() .map(String::toUpperCase) .forEach(System.out::println);

What are Default Methods in Interfaces?

▼

Default methods in interfaces have a body (implementation). Introduced in Java 8 to add new methods to interfaces without breaking existing implementing classes.

public interface Vehicle { void start(); // Default method default void stop() { System.out.println("Vehicle is stopping..."); } } public class Car implements Vehicle { @Override public void start() { System.out.println("Car is starting..."); } // Uses default stop() implementation }

How does @Transactional work in Spring Boot?

▼

@Transactional ensures atomicity by wrapping a method in a transaction. If a method fails, all database changes inside it rollback automatically.

@Service public class UserService { @Autowired private UserRepository userRepository; @Transactional public void createUser(User user) { userRepository.save(user); if (user.getName().isEmpty()) { throw new RuntimeException("User name cannot be empty"); } } }

Transaction Propagation Modes:

  • REQUIRED (default): Uses existing transaction or creates new one
  • REQUIRES_NEW: Always creates new transaction
  • MANDATORY: Requires existing transaction
  • SUPPORTS: Runs within transaction if exists

Spring Security

How do you secure a Spring Boot REST API?

▼

Common ways to secure Spring Boot REST APIs:

  • Basic Authentication: Uses username and password
  • JWT (JSON Web Token): Stateless authentication using tokens
  • OAuth2: Third-party authorization (Google, Facebook)
  • Role-Based Access Control (RBAC): Restrict access based on user roles
@Configuration @EnableWebSecurity public class SecurityConfig extends WebSecurityConfigurerAdapter { @Override protected void configure(HttpSecurity http) throws Exception { http.csrf().disable() .authorizeRequests() .antMatchers("/api/public").permitAll() .antMatchers("/api/private").authenticated() .and() .httpBasic(); } }

What is JWT (JSON Web Token) and how do you implement it?

▼

JWT is a compact, self-contained way to securely transmit information between client and server. It's commonly used for stateless authentication in REST APIs.

JWT Authentication Flow:

  1. Client sends username/password to /api/login
  2. Server validates credentials and generates JWT
  3. Client stores JWT (local storage/memory)
  4. Client sends JWT in Authorization: Bearer <token> header
  5. Filter verifies token before request proceeds
  6. If valid, server retrieves user identity from token claims
// JWT Utility Class public class JwtUtil { private static final SecretKey secretKey = Keys.secretKeyFor(SignatureAlgorithm.HS256); public static String generateToken(String username) { return Jwts.builder() .setSubject(username) .setIssuedAt(new Date()) .setExpiration(new Date(System.currentTimeMillis() + 86400000)) .signWith(secretKey) .compact(); } } // JWT Filter @Component public class JwtFilter extends OncePerRequestFilter { @Override protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain) { String token = request.getHeader("Authorization"); if (token != null && token.startsWith("Bearer ")) { Claims claims = JwtUtil.extractClaims(token.substring(7)); System.out.println("Authenticated User: " + claims.getSubject()); } chain.doFilter(request, response); } }

What is the difference between authentication and authorization?

▼
  • Authentication: Verifies who the user is (e.g., logging in with username/password)
  • Authorization: Determines what the user can access (e.g., Admin users can delete records)
http.authorizeRequests() .antMatchers("/admin/**").hasRole("ADMIN") .antMatchers("/user/**").hasAnyRole("USER", "ADMIN") .anyRequest().authenticated();

Microservices

What are microservices?

▼

Microservices is an architecture where an application is divided into small, independent services that communicate via APIs. Spring Boot supports microservices through:

  • Spring Cloud for distributed systems
  • Spring Boot Starter Dependencies for easy setup
  • Embedded servers for lightweight deployment
  • Resilience tools like Circuit Breakers (Resilience4j)

What is Spring Cloud?

▼

Spring Cloud provides tools to handle common microservices challenges:

  • Eureka: Service discovery
  • Feign: Simplifies REST communication between services
  • Ribbon: Client-side load balancing
  • API Gateway: Manages and secures API traffic

What is the role of Eureka Server and Eureka Client?

▼

Eureka Server: Acts as a service registry where microservices register themselves.

Eureka Client: Registers the service with Eureka Server and discovers other services dynamically.

// Eureka Server @EnableEurekaServer @SpringBootApplication public class EurekaServerApplication { public static void main(String[] args) { SpringApplication.run(EurekaServerApplication.class, args); } } // Eureka Client @EnableEurekaClient @SpringBootApplication public class MyServiceApplication { }

What is an API Gateway?

▼

API Gateway is a single entry point that routes requests to different microservices. It provides authentication, logging, rate limiting, and load balancing.

@SpringBootApplication @EnableDiscoveryClient public class ApiGatewayApplication { public static void main(String[] args) { SpringApplication.run(ApiGatewayApplication.class, args); } }

What is a Circuit Breaker?

▼

Circuit Breaker is a design pattern used to detect failures and prevent the system from repeatedly calling a failing service.

States:

  • Closed: Calls flow normally
  • Open: Calls are blocked (fallback is used)
  • Half-Open: Limited calls to check if service has recovered

What is the Saga Pattern?

▼

Saga Pattern breaks distributed transactions into multiple steps. If one step fails, compensating actions undo previous changes.

Example - Booking a Trip:

  1. Flight Service books a ticket ✅
  2. Hotel Service reserves a room ✅
  3. Payment Service charges the user ❌ (Fails)

Since payment fails, Saga triggers:

  • Hotel Service → cancel reservation
  • Flight Service → cancel ticket

What is the difference between Primary Key and Unique Key?

▼
Feature Primary Key Unique Key
Purpose Uniquely identifies each row Ensures uniqueness of column values
NULL Allowed? No Yes (one null in MySQL)
Number per Table Only one Multiple
Creates Index? Clustered index Non-clustered index

What is a composite key?

▼

A composite key is a combination of two or more columns in a table that together uniquely identify a row. It's used when a single column is not enough to uniquely identify a record.

What is a Foreign Key?

▼

A Foreign Key is a column (or set of columns) in one table that establishes a link between data in two tables. It refers to the Primary Key or Unique Key in another table, creating a relationship between the tables.

What is an Index?

▼

An index is a data structure that improves the speed of data retrieval from a table. Instead of scanning every row, the database uses the index to go directly to the row, similar to a book index.

What is Spring Data JPA?

▼

Spring Data JPA is a part of the Spring Data family that makes it easy to implement JPA-based repositories. It reduces boilerplate code by providing built-in CRUD operations and query methods.

@Repository public interface UserRepository extends JpaRepository<User, Long> { // Built-in CRUD methods: save, findById, findAll, delete, etc. // Custom query methods List<User> findByName(String name); List<User> findByAgeGreaterThan(int age); }

What is the difference between save() and saveAndFlush()?

▼
  • save(): Saves the entity but doesn't immediately flush to the database (waits for transaction commit)
  • saveAndFlush(): Saves the entity and immediately flushes to the database

▼

Synchronized Method: Locks the entire method, only one thread can execute it at a time.

1️⃣ What is Spring Boot, and how is it different from Spring Framework?

Spring Boot simplifies Spring development using auto-configuration, starters, and embedded servers. It eliminates boilerplate code and configuration required in traditional Spring Framework.

Key Differences:

  • Auto-configuration vs manual XML/Java configuration

2️⃣ What are the advantages of Spring Boot?

▼
  • Auto-configuration: Automatically configures application components based on dependencies
  • Embedded Server: Comes with Tomcat, Jetty, or Undertow - no external server needed
  • Starter Dependencies: Simplified dependency management with curated dependency sets
  • Less Boilerplate: Reduces XML and complex Java configurations
  • Production-Ready: Includes Actuator for monitoring, health checks, and metrics
  • Microservices Support: Designed for building microservices architecture

3️⃣ What is @SpringBootApplication?

▼

@SpringBootApplication is a meta-annotation that combines three annotations:

  • @Configuration: Defines beans in the Spring context
  • @EnableAutoConfiguration: Automatically configures Spring components based on classpath dependencies
  • @ComponentScan: Scans for Spring components (@Component, @Service, @Repository, @Controller) in the package and sub-packages
@SpringBootApplication public class MyApplication { public static void main(String[] args) { SpringApplication.run(MyApplication.class, args); } }

4️⃣ What is the role of spring-boot-starter dependencies?

▼

Spring Boot Starters are pre-defined dependency templates that group commonly used libraries to reduce configuration effort. They provide a group of commonly required dependencies for a particular functionality.

Common Starters:

  • spring-boot-starter-web: Spring MVC + Embedded Tomcat
  • spring-boot-starter-data-jpa: Hibernate + Spring Data JPA
  • spring-boot-starter-security: Spring Security for authentication
  • spring-boot-starter-test: JUnit, Mockito for testing

5️⃣ What is the default embedded server in Spring Boot? Can you change it?

▼

Default Server: Apache Tomcat is the default embedded server for Spring Boot web applications.

Can it be changed? Yes! You can replace Tomcat with Jetty or Undertow by excluding spring-boot-starter-tomcat and adding the new server dependency.

// Exclude Tomcat and add Jetty <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-web</artifactId> <exclusions> <exclusion> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-tomcat</artifactId> </exclusion> </exclusions> </dependency> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-jetty</artifactId> </dependency>

1️⃣1️⃣ What is Dependency Injection?

▼

Dependency Injection (DI) is a design pattern where Spring provides required dependencies instead of the developer creating objects manually using the new keyword. It helps maintain loose coupling between classes.

Spring's IoC (Inversion of Control) container manages the creation and lifecycle of objects (beans).

@Component public class ServiceA { public void process() { System.out.println("Processing..."); } } @Component public class Consumer { private final ServiceA serviceA; @Autowired public Consumer(ServiceA serviceA) { this.serviceA = serviceA; // Spring injects ServiceA } }

1️⃣2️⃣ What are the different bean scopes?

▼
  • Singleton (Default): Single instance created and shared across the application
  • Prototype: New instance created every time the bean is requested
  • Request: New instance per HTTP request (web applications only)
  • Session: New instance per HTTP session (web applications only)
  • Application: Single instance per ServletContext lifecycle
  • WebSocket: New instance per WebSocket connection

1️⃣3️⃣ Difference between @Autowired and @Qualifier?

▼

@Autowired: Automatically injects dependencies by type. Used when there's only one bean of the required type.

@Qualifier: Used when multiple beans of the same type exist. It helps select a specific bean by name to inject.

@Service @Qualifier("creditCardService") public class CreditCardPaymentService implements PaymentService { } @Service public class PaymentProcessor { @Autowired @Qualifier("creditCardService") private PaymentService paymentService; }

1️⃣4️⃣ How do you define a Prototype bean?

▼

Use @Scope("prototype") with @Component or @Bean annotation to define a prototype bean.

// Using @Component @Component @Scope("prototype") public class PrototypeService { } // Using @Bean @Configuration public class AppConfig { @Bean @Scope("prototype") public PrototypeService prototypeService() { return new PrototypeService(); } }

1️⃣5️⃣ Difference between field, constructor, and setter injection?

▼
  • Field Injection: Uses @Autowired directly on fields. Not recommended - makes testing harder and doesn't support immutability.
  • Constructor Injection (Recommended): Injects via constructor. Best for mandatory dependencies, supports immutability, simplifies testing.
  • Setter Injection: Injects via setter methods. Useful for optional dependencies that may change during runtime.
// Constructor Injection (Recommended) @Component public class Consumer { private final ServiceA serviceA; @Autowired public Consumer(ServiceA serviceA) { this.serviceA = serviceA; } } // Setter Injection @Component public class Consumer { private ServiceA serviceA; @Autowired public void setServiceA(ServiceA serviceA) { this.serviceA = serviceA; } }

6️⃣ What is the difference between @Component, @Service, and @Repository?

▼

All three annotations create Spring-managed beans, but they serve different purposes:

  • @Component: Generic annotation for any Spring-managed component
  • @Service: Specialization of @Component for business logic layer. Indicates service-layer classes.
  • @Repository: Specialization of @Component for data access layer. Provides exception translation for database errors.

7️⃣ What is @RestController vs @Controller?

▼
  • @Controller: Used for traditional MVC applications. Returns views (HTML/JSP/Thymeleaf). Requires @ResponseBody to return data.
  • @RestController: Used for REST APIs. Returns response data directly (JSON/XML). It's a combination of @Controller + @ResponseBody.
@RestController @RequestMapping("/api") public class ApiController { @GetMapping("/users") public List<String> getUsers() { return List.of("Umesh", "Rahul"); // Returns JSON automatically } }

8️⃣ What is the purpose of @Bean?

▼

@Bean is used to explicitly define a Spring-managed bean, usually inside a @Configuration class. Unlike @Component, it's used for third-party classes or when custom initialization is needed.

@Configuration public class AppConfig { @Bean public DataSource dataSource() { return new HikariDataSource(); } }

9️⃣ @ConfigurationProperties vs @Value?

▼
  • @Value: Used for individual property values. Good for single properties.
  • @ConfigurationProperties: Binds a group of related properties to a POJO. Better for structured configuration with multiple related values.
// Using @Value @Value("${app.name}") private String appName; // Using @ConfigurationProperties @Component @ConfigurationProperties(prefix = "app") public class AppProperties { private String name; private String version; // Getters and Setters }

🔟 How does @Transactional work?

▼

@Transactional manages database transactions. It ensures atomicity - if a transaction fails according to rollback rules, all changes can be rolled back automatically.

@Service public class UserService { @Autowired private UserRepository userRepository; @Transactional public void createUser(User user) { userRepository.save(user); if (user.getName().isEmpty()) { throw new RuntimeException("Name cannot be empty"); } // If exception thrown, transaction rolls back } }

2️⃣1️⃣ How do you secure a Spring Boot REST API?

▼

Use Spring Security with multiple approaches:

  • Basic Authentication: Username/password based authentication
  • JWT (JSON Web Token): Stateless token-based authentication
  • OAuth2: Third-party authorization (Google, Facebook, etc.)
  • Role-Based Access Control (RBAC): Restrict access based on user roles
  • CORS Configuration: Allow or restrict cross-origin requests

2️⃣2️⃣ What is JWT and how is it implemented?

▼

JWT (JSON Web Token) is a token-based authentication mechanism. After authentication, the server generates a signed JWT token. The client sends this token (usually as a Bearer token in the Authorization header) with subsequent requests to prove identity.

JWT Flow:

  1. Client sends credentials to /login endpoint
  2. Server validates and generates JWT token
  3. Client stores token (localStorage/memory)
  4. Client sends token in Authorization: Bearer <token> header
  5. Server validates token and grants access

2️⃣3️⃣ What is OAuth2?

▼

OAuth2 is an authorization framework that allows applications to access protected resources using access tokens. It enables third-party services (like Google, Facebook) to grant access without sharing user credentials directly.

OAuth2 Flow:

  1. User clicks "Login with Google"
  2. App redirects to Google authentication page
  3. After authentication, Google redirects back with authorization code
  4. App exchanges code for access token
  5. Token is used to access protected resources

2️⃣4️⃣ Authentication vs Authorization?

▼
  • Authentication: Verifies who the user is (identity). Example: Logging in with username and password.
  • Authorization: Determines what the user can access (permissions). Example: Admin users can delete records, but normal users cannot.
// Authentication: Who are you? // Authorization: What are you allowed to do? http.authorizeRequests() .antMatchers("/admin/**").hasRole("ADMIN") .antMatchers("/user/**").hasAnyRole("USER", "ADMIN") .anyRequest().authenticated();

1️⃣5️⃣ What is Normalization?

▼

Normal Forms:

1️⃣6️⃣ What is ACID property in database transactions?

▼

  • Consistency: Database remains in a consistent state before and after transaction
  • Isolation: Transactions don't interfere with each other
  • Durability: Committed transactions remain permanent even after system failure
// Transaction Example BEGIN TRANSACTION; UPDATE accounts SET balance = balance - 1000 WHERE id = 1; UPDATE accounts SET balance = balance + 1000 WHERE id = 2; COMMIT; // or ROLLBACK;

▼

This procedure uses REPEAT loop which always executes at least once.
